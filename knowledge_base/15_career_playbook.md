## 15.6 AI PM 真实面试题库(18 道,Aakash Gupta 教练 47 名学员进入 $300K+ AI PM 岗位的整理)

Aakash 给出比例:**Behavioral 35% / AI Product Sense 20% / AI Execution 15% / Technical Depth 15% / Case 15%**。

### AI Product Sense

1. **"为 ChatGPT 设计一个企业版 Agent 入口,怎么做?"**
   提示:JTBD → 用户人群(IT admin vs end user)→ 三条 agent 链 → 怎么衡量 task completion vs hallucination → cost ceiling

2. **"假设我们要给 Notion 加一个 AI Tasks 功能,你怎么定 success metric?"**
   提示:除 DAU、retention,必须给 *grounded* 的 task success rate、reversal rate(用户撤销)、time-to-first-value

3. **"如何为客服 AI 设定可接受的幻觉率?"**
   提示:分场景 —— playlist 推荐 2% 可接受;福利结算 0% 可接受。给出 Eugene Yan 的 task-specific eval 思路

### AI Execution / Eval(最常见,权重最高)

4. **"给我一个 LLM-as-Judge 的评估方案,你怎么避免 judge 偏见?"**
   提示:Hamel & Shreya 路线 —— 先 error analysis 在 30-50 traces 上分类失败模式 → 写 binary judges 而不是 5-point Likert → 用 human-labeled holdout 算 judge 与人类 Cohen's kappa

5. **"如何防止一个 ReAct agent 陷入 hallucination loop?"**
   提示:strict tool validation(白名单)、max-steps cutoff、reflection step、cost budget、fallback to human

6. **"你怎么决定用 RAG 还是 fine-tune?"**
   提示:Chip Huyen 口诀:**"RAG 解知识 gap,fine-tune 解行为 gap"**。法律检索 → RAG;统一格式输出 → fine-tune

7. **"设计一个 production eval pipeline。"**
   提示:Offline eval set + LLM judge + human spot check + canary deploy + online quality metric + regression alerts。要提到 Arize、Braintrust、LangSmith

8. **"模型从 Claude 4.5 升级到 4.7,你怎么验证不会回退?"**
   提示:Golden set 回归、A/B canary、cost/latency 监控、结构化输出 schema 校验、subset by difficulty bucket

### Technical Depth

9. **"快速解释 churn classifier 怎么做。"** *Aakash 警告:如果你回答"我会用 LLM…"已被打低分。*
   **正确答案**:用 XGBoost —— 更便宜、更确定、更可解释

10. **"什么时候不该用 agent?"**
    提示:任务可被一个 SQL 查询/确定性 pipeline 解决、成本敏感、latency < 200ms 要求、幻觉零容忍

11. **"context window 12K vs 200K,怎么选?"**
    提示:cost、latency、attention 衰减(Lost in the Middle)、是否需要 summarization step

### Case / Trade-off

12. **"用户抱怨 AI 助手太慢但 CSAT 很高,怎么办?"**
    提示:定位是 perceived latency 还是 time-to-first-token;引入 streaming、optimistic UI、speculative decoding

13. **"成本超预算 3x,但你还想保留质量,三个杠杆?"**
    提示:模型路由、prompt 缓存、batched 调用 + 关闭 chain-of-thought / 缩短 reasoning

### Behavioral / Safety(Anthropic 必考)

14. **"讲一次你拒绝 ship 一个 AI feature 的经历。"**
    提示:STAR;强调 eval gap、失败模式、stakeholder management

15. **"如果你的 model 上线第二天发现 systematic bias,你的前 24 小时计划?"**
    提示:rollback → 收集失败 traces → 召集 RCA → 透明对外沟通 → 加 eval case 防回归

16. **"AI 安全责任怎么在 PM、研究、Trust & Safety 之间分?"**
    提示:PM owns 产品风险面、研究 owns 模型能力面、T&S owns 滥用面;三方共建 red-team & eval calendar

17. **"用一个例子说明你如何用 AI 提升自己产出 10x。"**
    提示:实操:用 Claude Code 写 PRD scaffolding、用 Lovable 24h 出 prototype、用 Cursor 自动跑 eval

18. **"OpenAI/Anthropic 文化里,PM 与研究科学家怎么协作?"**
    提示:PM 要会读 paper、能跑 eval、能用 product 反馈 narrow 研究方向;**忌"transactional PRD 提交"**

## 15.9 工程师 → AI PM 12 周计划(不同起点)

工程师起点:**已会写代码、读过 paper、能搭 RAG**;薄弱:**用户研究、PRD、roadmap、stakeholder management、eval rubric 设计**(不是 metric)。

| 周 | 主题 | 关键交付 |
|---|------|---------|
| **W1** | 跳过技术补强,直奔产品 sense | 看 Cagan 全集 → 给当前产品写"我作为 PM 会推翻什么"memo |
| **W2** | 客户访谈实战 | 跑 5 个客户访谈,整理成 insight + JTBD map |
| **W3** | PRD + roadmap | 给一个真实 feature 写完整 PRD(problem→opp→solution→eval→GTM) |
| **W4** | **Eval rubric 设计** | 用 Hamel 的 error analysis 方法,对一个开源 LLM app 跑 50 traces,提炼 8 个失败类别 |
| **W5** | 用户体验 + UX for AI | 重设计一个 AI feature 的 UX 流(含 hallucination 处理、引用、reversibility) |
| **W6** | Stakeholder management | 准备一份 quarterly review deck(用真实数据) |
| **W7** | 商业模型 + 定价 | 给一个 AI feature 设计 pricing model |
| **W8** | 安全 + 合规(GDPR、SOC2、AI Act) | 写 risk register + 数据流图 |
| **W9** | 用 AI 加速 PM 工作流 | 自建 PM OS 仓库,至少 5 个自动化脚本 |
| **W10** | Portfolio:选**产品决策**类项目 | 公开 1 份 product strategy memo + 1 个 eval blog post |
| **W11** | 面试转型话术 | 录制 5 段 STAR 故事;练 product sense 题 |
| **W12** | 内推 + onsite | 目标:≥2 个 onsite,且不被卡在"你过于技术"标签 |

**给工程师的关键提醒**(Aakash 教练经验):面试官最怕"工程师空降 PM"无视用户。**所以在 product sense 题里永远从用户痛点开始,不从技术架构开始。** XGBoost vs LLM 那道题就是经典陷阱。
